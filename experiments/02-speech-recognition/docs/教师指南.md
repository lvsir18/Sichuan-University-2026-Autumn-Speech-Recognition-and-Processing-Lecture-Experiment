# 教师指南

## 教学组织

建议按“预测—运行—解释—复核”组织每次实验。学生先写出对参数变化的预测，再运行平台，最后用导出的 JSON 支撑结论。三个实验可安排为 6 学时，也可合并为一次 3 学时综合实验。

## 演示与实测的边界

内置演示用于确保无网络、低配置机房也能完成流程，返回值带 `metadata.mode = simulated`。真实 Faster-Whisper 结果带 `measured`。评分时应检查学生是否清楚区分二者。

## 推荐评分量表（100 分）

| 项目 | 分值 | 要求 |
| --- | ---: | --- |
| 实验设计 | 20 | 自变量、因变量、控制变量明确 |
| 操作与记录 | 25 | 参数、设备、输入、原始 JSON 完整 |
| 指标理解 | 25 | 正确解释 CER/WER/SER/RTF 及局限 |
| 结果分析 | 20 | 结论由数据支持，不以单样本过度概括 |
| 可复现性 | 10 | 能用 Docker 和相同配置复现实验 |

## 真实实验建议

- 机房 CPU 内存建议不低于 8 GB，先用 tiny/base。
- 课前由教师在一台机器点击“下载并校验数据集”，确认 `FLEURS-CMN-MINI-12-v1` 可访问；机房网络受限时，可导出 Docker 数据卷或将已校验目录分发到各机器。
- 模型首次下载后保存在 Docker 命名卷 `asr-models`，重建容器不会重复下载。
- 固定数据集保存在 `asr-dataset` 命名卷；每条音频都按预置 SHA-256 白名单校验。评分时要求学生报告数据集标识 `FLEURS-CMN-MINI-12-v1`。
- 统一规定文本规范化、模型版本、容器镜像和运行设备，否则横向成绩不可比。
