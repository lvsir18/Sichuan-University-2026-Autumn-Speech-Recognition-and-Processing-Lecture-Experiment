# 课程实验统一规范

## 每个实验必须包含

```text
README.md
Dockerfile
docker-compose.yml
.env.example
requirements.txt（Python 项目）
docs/（学生指导书与教师说明）
scripts/（数据与模型准备）
tests/（无需下载大模型即可运行的基础测试）
```

## README 最低内容

1. 实验目标和教材知识点。
2. 数据集名称、固定版本/子集、许可证和准备方法。
3. 模型名称、来源、许可证和缓存位置。
4. 一键部署、停止和清理命令。
5. 实验步骤、控制变量、评价指标和结果导出方法。
6. CPU/GPU、内存、磁盘和网络要求。
7. 演示数据、模拟结果和真实测量结果的边界。

## Docker 约定

- 服务名和 Compose 项目名包含实验编号，避免数据卷冲突。
- 模型和数据使用独立命名卷，不写入镜像，也不提交 Git。
- 提供健康检查和可覆盖的宿主机端口。
- 依赖锁定版本；CPU 作为最低可运行配置，GPU 为可选 profile。
- 上传文件设置大小限制并使用临时目录，处理结束后清理。

建议默认端口：实验一 `8001`、实验二 `8002`、实验三 `8003`、实验四 `8004`。若单独运行实验，可以通过 `.env` 改为其他端口。

## 数据与评测

- 固定用于班级横向比较的样本 ID，并生成哈希清单。
- 准确记录预处理、模型、参数、运行设备和耗时口径。
- 单样本结果不得表述为模型整体性能。
- 仅处理获得授权的音频；涉及个人声音时说明同意、保存期限和删除方法。

## 验收

每个实验合并前至少完成：代码静态检查、单元测试、Compose 配置解析、一次无模型演示流程，以及条件允许时的一次真实模型冒烟测试。
